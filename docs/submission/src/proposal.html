1. Problem statement

Students and families collect paper slips (parchi in Hindi): fee receipts, pharmacy bills, shop and GST tax invoices. They matter later for reimbursements, scholarships, insurance claims and tax filing, but they are rarely organised. Typing the vendor, date, amount and GST from each slip into a spreadsheet is slow and error-prone, and the slips fade or get lost.

A traditional solution would run an OCR server all day. But uploads are bursty and unpredictable: nothing for hours, then dozens at the end of a month or a semester. An always-on server is paid for while idle and still struggles with a burst. This is the kind of workload that serverless, event-driven cloud computing is designed for.

2. Proposed solution

Parchi is a web application where a user uploads a photo or PDF of a bill. A chain of managed AWS services then reads it, checks it, files it and emails a confirmation, with no server running at any point:

  1. The browser asks API Gateway for a one-time upload link; a Lambda function checks the type, size and daily limit.
  2. The file is uploaded directly to Amazon S3 (it never passes through our code).
  3. S3 fires an event into an SQS queue, which buffers bursts and retries failures (dead-letter queue after 3 tries).
  4. A Lambda worker reads the bill with OCR (Amazon Textract, or the open-source Tesseract engine in a container image).
  5. The fields are validated (totals reconcile, GSTIN checksum, plausible date) and stored in DynamoDB.
  6. SNS emails the owner; a web dashboard shows each bill moving through the pipeline live.

3. Objectives

  1. Secure direct uploads of JPEG, PNG and PDF bills (up to 10 MB) from a browser using presigned S3 URLs.
  2. Automatic extraction of vendor, date, total, tax (CGST + SGST), bill number and line items, normalising Indian formats (₹ with lakh grouping, dd/mm/yyyy dates, GSTIN).
  3. Asynchronous, reliable processing: an event-driven S3 → SQS → Lambda pipeline with retries, no duplicate processing (idempotency) and a dead-letter queue with alarms.
  4. Trustworthy results: cross-checks on every bill, with doubtful ones flagged "needs review" for a human to correct.
  5. Per-user email notifications through one SNS topic with subscription filter policies.
  6. A live dashboard showing every document's position in the pipeline, with timings, a ledger and spending charts.
  7. Elastic and cost-controlled: scale from zero automatically, cost nothing while idle, cap daily uploads.
  8. Infrastructure as code: the entire system defined in one AWS SAM template and deployed with one command.

5. Expected outcomes

  • A working, deployed system on AWS that turns a bill photo into a filed, validated record and an email in a few seconds.
  • A demonstration of core cloud concepts: FaaS, event-driven design, elasticity, managed services, least privilege, IaC.
  • A public GitHub repository with README, automated tests and deployment scripts; a report with results and cost analysis.
